### [Principle] D6 — QuickJS top-level-await needs out-of-scope pumping
`Promise::finish()` returns Err(WouldBlock) whenever the job queue drains before a TLA fetch/TLS promise settles; blocking it inside `Context::with` deadlocks ("Error blocking on a promise resulted in a dead lock"). Pattern that worked: evaluate WITHOUT finish, attach JS settlement glue writing flags to `globalThis`, then pump fd pumps (HTTP/fetch/timers) + `execute_pending_job()` strictly BETWEEN `with` scopes — pumping jobs while a scope is open re-enters the RefCell and panics.

### [Dead End] D7 — Slot release keyed on header state leaks active work
Releasing engine slots only when `!headersResolved` left fetch slots counted active after body consumption, so `cz-js` never exited (probe: `active=1 live=[1] rc null`). Correct guard: terminal (`closed`) AND zero pending reads, regardless of buffered/stream mode, invoked at EVERY terminal point (buffered consume, reader `done`, cancel, drain fan-out). Symptom signature: correct stdout output but process hangs → check live-id registry first.

### [Insight] D8 — rquickjs 0.14 API facts verified from source, not docs
`Promise::then()/catch()` return Functions whose detached `.call(fnArg)` throws ("Exception generated by QuickJS") because `this` isn't bound — pass `promise.into_value()` into a JS glue function instead of wiring Rust callbacks; `Value` implements neither Display nor `to_string()` (use `Coerced::<String>::from_js`, needs `FromJs` in scope); importing `rquickjs::Result` shadows std `Result` (2-arg usages break); under `-D warnings`, unused imports/dead code must be pruned exactly per rustc's list (`#[cfg(test)]` for test-only helpers).

### [Insight] D11 — ureq v3 + rustls integration facts (source-verified)

### [Dead End] D12 — Gate stderr regex needs name+message first line

### [Principle] D13 — Orderly TLS shutdown ordering in raw-handshake tests
Echo-style rustls tests must exchange plaintext BEFORE joining the server thread: server bounded-waits (~700 ms, `WouldBlock` sleep loop) for the client's `close_notify`, both sides call `send_close_notify()`, and only THEN join — joining earlier deadlocks both ends. ### [Note] D14 — Process-scoped caches vs CA env tests
Root-store `OnceLock` (`crates/cz-net/src/tls.rs`: "cz-js invocation is its own process so a OnceLock is safe here") means SSL_CERT_FILE/NODE_EXTRA_CA_CERTS tests must run as SEPARATE subprocesses, not in-process env mutation; the locked gate deletes SSL_CERT_FILE/SSL_CERT_DIR/NODE_EXTRA_CA_CERTS (`clearSslEnv`) per spawn for exactly this reason. Never assert cache-hit/miss by flipping env inside one test binary — use child processes or an uncached loader path (`load_system_roots_uncached`).

### [Insight] D15 — rustls self-signed leaf presented as its own CA
rustls' stock webpki verifier rejects Node-style `ca: <self-signed leaf>` with webpki `CaUsedAsEndEntity`, which maps to `CertificateError::Other(OtherError(..))` whose `PartialEq` always returns false (`rustls-0.23.46/src/error.rs:1051`), so typed matching is impossible: identify it by Debug text (`format!("{other:?}").contains("CaUsedAsEndEntity")`). Fix pattern: build `WebPkiServerVerifier::builder_with_provider(roots, ring)` and wrap it in a delegating `ServerCertVerifier` that accepts ONLY when the wire end-entity byte-matches a provided anchor; everything else fails closed. Evidence: `SelfSignedTolerantVerifier` in `crates/cz-net/src/tls.rs` + real-handshake test `tls_self_signed_leaf_as_ca_is_accepted_and_unrelated_ca_rejects` (fixtures `testdata/self-cert.pem/self-key.pem`, openssl `-addext subjectAltName=DNS:localhost`).

### [Principle] D16 — Top-level await settlement without Promise::finish
`Promise::finish()` spins only the QuickJS job queue → returns `WouldBlock` (runner printed "Error blocking on a promise resulted in a dead lock") whenever the awaited value depends on out-of-band worker threads (fetch/TLS). Correct runner shape: evaluate the module inside `ctx.with` WITHOUT finishing it, attach settlement via a tiny JS glue function that writes flags/error text onto `globalThis`, then pump HTTP/fetch/timers + `execute_pending_job()` ONLY outside every context scope (rquickjs RefCell rule), polling the flags through brief `ctx.with` reads between drains; idle-grace counter detects true deadlock and exits 1. Evidence: `MODULE_GLUE`/`start_module`/`settle_module` in `crates/cz-runner/src/main.rs` (:193/:222/:248), Phase 8A gate tests 9–11 (SSE + AbortSignal) pass with top-level await.

### [Dead End] D17 — Calling Rust closures through promise.then from Rust
`promise.then()?.call((rust_function,))` throws "Exception generated by QuickJS": retrieving `then` as a Function value and calling it detaches `this` from the promise. Do NOT hand-roll settlement in Rust this way; wire `.then/.catch` inside JavaScript (glue receives the module promise value via `Promise::into_value()`) so normal method-binding applies. Evidence: same runner path after switching to `__czWireModule(promise)` (`crates/cz-runner/src/main.rs:222-236`), TLA smoke + locked verifier green.
